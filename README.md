# 文章双平台评分器

一个纯前端的文章质量评分工具：粘贴一篇文章，同时从 **今日头条** 与 **微信公众号** 两个平台视角，给出**准确性**、**原创度**评分，并给出全局 **AI 重合度**，附一句话总评、扣分点与可执行的修改建议。

单文件、无构建、无后端、无依赖，双击 `index.html` 即可运行。

> 免责声明：本评分由大模型或本地规则自动生成，仅供参考，**不构成事实核验或法律意见**。评分不能替代人工核查，发布前请自行核实文中的数据、引用与结论。

***

## 特性

- **开箱即用**：默认「免 Key 自动」引擎，不用注册、不用填 Key，点击开始即自动联网打分。
- **5 个维度**：今日头条准确性 / 原创度、微信公众号准确性 / 原创度、全局 AI 重合度（0–100）。
- **结构化输出**：每个维度含一句话总评 + 2–4 条具体扣分点或亮点；另有 3–5 条综合建议与两个平台的「发布前重点」。
- **可视化**：环形进度 + 数字，绿（好）/ 橙（中）/ 红（差）；AI 重合度做了方向反转，**越低越绿**。
- **一键复制**：支持复制为 Markdown 或纯文本，方便贴到文档、飞书、Notion。
- **异常友好**：空输入、超长输入、限流排队、HTTP 错误、超时、模型返回非 JSON 都有明确提示与重试入口。
- **响应式**：移动端单列布局，支持浅色 / 深色切换。
- **隐私可控**：三种引擎可选，含完全离线的本地规则模式。

## 快速开始

### 本地使用

下载 `index.html`，双击用浏览器打开即可，无需安装任何依赖。

### 部署到 GitHub Pages

```bash
git init
git add index.html README.md .nojekyll
git commit -m "feat: 文章双平台评分器"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

然后在仓库 **Settings → Pages** 中把 Source 设为 `main` 分支的 `/ (root)`，稍等片刻即可通过
`https://<你的用户名>.github.io/<仓库名>/` 访问。

> `.nojekyll` 用于跳过 GitHub Pages 的 Jekyll 处理，避免静态资源被过滤。

## 三种评分引擎

| 引擎               | 是否需要 Key | 联网 | 说明                                                                                                       |
| ---------------- | -------- | -- | -------------------------------------------------------------------------------------------------------- |
| **免 Key 自动**（默认） | 不需要      | 是  | 调用公共免费接口 [Pollinations](https://pollinations.ai)（OpenAI 兼容协议）。匿名额度约为同一 IP 每 45 秒 1 次，被限流时自动排队重试（最多 3 次）。 |
| **自定义 API**      | 需要       | 是  | 填自己的 Base URL / Key / 模型名，兼容 OpenAI Chat Completions 协议，可对接 DeepSeek、通义千问、OpenAI、本地 Ollama 等。            |
| **本地规则**         | 不需要      | 否  | 完全离线，用句式与关键词特征粗略估计 AI 重合度；准确性与原创度仅给可核查的提示点，不打分。                                                          |

自定义 API 的服务商预设已内置：

| 服务商        | Base URL                                            | 模型示例            |
| ---------- | --------------------------------------------------- | --------------- |
| DeepSeek   | `https://api.deepseek.com/v1`                       | `deepseek-chat` |
| 通义千问（兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`     |
| OpenAI     | `https://api.openai.com/v1`                         | `gpt-4o-mini`   |
| 本地 Ollama  | `http://localhost:11434/v1`                         | `qwen2.5:7b`    |

## 评分口径

**准确性** —— 事实是否站得住脚。核查数据 / 人名 / 公司 / 时间 / 政策是否可信，有无夸大与标题党式误导，逻辑是否自洽，结论是否有依据。

**原创度** —— 内容是否独特、是否洗稿。核查表达是否与网络常见模板高度重合，信息密度是否足够，观点与案例是否新鲜，是否只是换了词的重排。

**AI 重合度** —— 文本呈现 AI 生成特征的概率，**数值越高越像 AI 生成**。典型痕迹：密集三连排比、对称套句、「值得注意的是 / 换句话说」类过渡、总分总模板、空洞金句、段落长度高度均匀、缺乏具体细节与个人化语气。

**平台差异**

- **今日头条**：更看重时效热点、具名公司与硬数据、可被反驳的明确判断、点击吸引力；对标题党和情绪化容忍度较高，但反感泛泛而谈的行业观察。
- **微信公众号**：更看重底层逻辑、结构清晰、读者获得感与原创观点；对标题党、低质洗稿零容忍，准确性侧重论据是否扎实、有无误导读者。

## 隐私说明

- 本页面**没有自有后端、无埋点、无统计**，文章只会在浏览器与评分接口之间传输。
- **「免 Key 自动」模式**会把文章正文发送给第三方公共免费服务 Pollinations（`text.pollinations.ai`）以完成打分。请勿用它处理敏感或未公开内容；如有顾虑请改用「自定义 API」或「本地规则」。
- 「自定义 API」模式只发送到你填写的 API 地址；「本地规则」模式全程离线，**不发出任何网络请求**。
- API Key 与配置仅保存在当前浏览器的 `localStorage`，不会外发；可随时点「清除密钥」删除。

## 常见问题

**提示「免费接口排队中」**
公共接口对匿名访问限流（约每 45 秒 1 次），页面会自动等待并重试。急着用可切到「自定义 API」。

**免 Key 模式失败**
公共免费服务可能临时不可用。稍后重试，或点「改用本地规则」立刻拿到粗略结果。

**提示网络失败 / CORS**
部分服务未开放浏览器跨域访问。可换用支持 CORS 的服务商；本地 Ollama 需设置 `OLLAMA_ORIGINS=*` 后重启 Ollama。

**HTTP 401 / 403 / 404**
401、403 多为 Key 错误或没有该模型权限；404 多为 Base URL 少了 `/v1` 或多了路径。

**返回不是 JSON**
页面会展示模型的原始返回内容。可尝试关闭「流式输出」、更换模型，或点「重新评分」。

**文章长度限制**
上限 10000 字符，超出会被拦截并提示；建议把长文拆成正文段落再评分。

## 技术说明

- 纯静态单文件，无构建步骤、无第三方运行时依赖，仅调用所配置的 OpenAI 兼容接口。
- 系统提示词约束模型只输出严格 JSON；前端对返回做容错：剥离 Markdown 代码块与多余前言、字段缺失降级为「未评分」、分数自动裁剪到 0–100。
- 支持 SSE 流式输出（实时预览生成过程、可随时取消）；若服务端按普通 JSON 返回会自动退回一次性解析。
- 超时保护 180 秒；限流（402 / 429）时读取 `Retry-After` 或错误信息中的等待秒数自动排队重试。
